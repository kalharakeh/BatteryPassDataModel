## Admin UI Checks For These Accounts

- `/admin/clusters?tab=batteries` shows the generated Battery IDs in the Batteries dense table. Use it to copy current IDs after reset.
- `/admin/clusters?tab=battery` is the Battery cluster assignments page. It shows one row per battery and only the controls needed to change the battery's cluster assignment.
- `/admin/clusters?tab=users` shows Username and Email as separate columns and shows only the Cluster memberships count in the table row.
- A user can have multiple cluster memberships. Open the inline row drawer from the users table to add/remove memberships, set each membership role, edit profile/access, or change password with confirmation and the reveal icon.
- The account email is read-only in the user drawer. Use Username/name for editable display identity.
- `/admin/clusters?tab=local-editable-fields` has sections collapsed by default.
- `/help` and `/admin/help` use inline row detail panels. Expanding a detail opens the panel directly below the selected row.

Normal users can open the detailed report for their own cluster battery only. The customer account `customer_001_001@customer.org` can open North batteries including `CP7M-NORTH-001`; it should not open South, Fleet, Demo API, or unassigned detailed reports.

## Fixed Demo API Tokens

Reset data creates fixed QA tokens scoped to `demo-cluster` so the `/help` examples work immediately.

Use Token Value in the `Authorization` header. The Token ID shown in API Token Management is a copyable admin record identifier and is not the secret credential. In the dense token table, Scope shows a scope count; opening the details lists cluster names without repeating cluster IDs in the visible scope text.

| Token type | Token value |
| --- | --- |
| Read | `SAMPLEBATTERYPASSPORTREADTOKN001` |
| Read-write | `SAMPLEBATTERYPASSPORTWRITETOK001` |
| Validate/sign/publish | `SAMPLEBATTERYPASSPORTSIGNTOK001` |

## Battery Family Reset

Press **Reset battery-family passports** on `/admin/clusters?tab=products` or `/admin/help` to recreate eight batteries and nine passport snapshots: one unassigned demonstrator, one Demo API battery with two passports, and six customer/fleet batteries. The reset removes older sample/demo passports so the acceptance test set stays small and predictable.
